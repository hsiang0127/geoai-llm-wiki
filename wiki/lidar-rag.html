光達（LiDAR）操作手冊與測量法規 RAG 檢索系統

建立日期：2026-11-16 關鍵技術：LiDAR、RAG、Hybrid Search、LAS 1.4、TWD97 狀態：技術架構設計筆記

1. 問題背景與空間文件檢索痛點

在光達（LiDAR）實務作業中，無論是地面光達（TLS）或空載／無人機光達（ALS / UAV-LiDAR），測量人員常需同時查閱數百頁的英文儀器操作手冊、點雲後處理軟體參數說明，以及國內測繪作業規範（例如點雲密度標準、高程檢核點中誤差容許值、LAS 1.4 分類碼定義與 TWD97 / TWVD2001 坐標基準轉換）。

若直接向通用大模型提問，模型極易因訓練資料混雜不同機型與過時法規而產生數字或參數幻覺（Hallucination）。透過建置領域專用的 RAG（檢索增強生成） 系統，可讓 AI 先精準檢索官方手冊與法規原文，再產出附帶頁碼出處的工程級回答。

2. 光達領域 RAG 核心架構設計

步驟一：結構化切片與規格表保留（Structure-Aware Chunking）

測量手冊包含大量多欄規格表（例如掃描脈衝重複頻率 PRF、測距精度、最小點距與最大作業航高）。切片時需以 Markdown 表格保留完整列資訊，並為每個切片掛載 doc_name、device_model、chapter 與 page 等 Metadata。

步驟二：混合檢索（Hybrid Search：Embedding + BM25）

單靠向量語意檢索（Embedding）對「點雲分類代碼 2 代表地面點」、「PDOP 上限」或特定錯誤碼（如 ERR_IMU_INIT）容易失準。因此應結合 BM25 關鍵字比對與向量檢索，並以交叉編碼器（Reranker）進行重排序。

步驟三：強制條文溯源輸出（Citation-Grounded Generation）

在系統 Prompt 中嚴格限制：所有數值規範（如 RTK 固定解初始化時間、檢核點中誤差門檻）必須附帶檢索來源的文件名稱與章節頁碼；若知識庫未收錄該條文，AI 必須明確回答「手冊未記載」，禁止自行推估。

3. Python 光達文件 RAG 檢索原型範例

以下示範使用 Python 建立具備 Metadata 過濾與來源引用格式化的光達手冊 RAG 檢索管線原型： 

from dataclasses import dataclass

@dataclass
class LidarDocChunk:
    doc_name: str
    device_model: str
    section: str
    page: int
    content: str

# 1. 模擬切片後的光達手冊與測量法規知識片段
KNOWLEDGE_CHUNKS = [
    LidarDocChunk(
        doc_name="UAV-LiDAR_L2_User_Manual_v2.pdf",
        device_model="Zenmuse L2",
        section="4.2 航線規劃與點雲密度建議",
        page=38,
        content="一般地形測繪建議航高 50-150 m，航向重疊率 >= 70%，旁向重疊率 >= 50%；啟用三回波模式可提升林下地面點穿透率。"
    ),
    LidarDocChunk(
        doc_name="UAV-LiDAR_L2_User_Manual_v2.pdf",
        device_model="Zenmuse L2",
        section="5.1 IMU 慣導校準規範",
        page=46,
        content="起飛前須於空曠處完成 RTK 固定解收斂，並依任務需求每隔 100 秒或直線飛行 1000 公尺執行一次 8 字形或加減速 IMU 校準。"
    ),
    LidarDocChunk(
        doc_name="空載光達測繪作業規範_112修訂版.pdf",
        device_model="通用法規",
        section="第 3 章 成果精度檢核",
        page=14,
        content="基本地形圖測製之裸露平坦地區，點雲高程中誤差（RMSEz）應小於 15 公分；輸出格式須符合 ASPRS LAS 1.4 標準並註記 TWD97 / TWVD2001 坐標系統。"
    ),
]

def hybrid_retrieve(query: str, model_filter: str | None = None, top_k: int = 2) -> list[LidarDocChunk]:
    """簡易混合檢索模擬：結合型號 Metadata 過濾與關鍵字權重計分。"""
    terms = [t.lower() for t in query.replace("，", " ").split() if t.strip()]
    scored = []

    for chunk in KNOWLEDGE_CHUNKS:
        if model_filter and chunk.device_model not in (model_filter, "通用法規"):
            continue
        text_lower = f"{chunk.section} {chunk.content}".lower()
        score = sum(1 for t in terms if t in text_lower)
        # 針對常見空間名詞補充語意加權模擬
        if "精度" in query and "中誤差" in chunk.content:
            score += 2
        if "校準" in query and "imu" in text_lower:
            score += 2
        if score > 0:
            scored.append((score, chunk))

    scored.sort(key=lambda x: x[0], reverse=True)
    return [item[1] for item in scored[:top_k]]

def build_rag_prompt(query: str, retrieved: list[LidarDocChunk]) -> str:
    """組裝強制附帶出處引用的 LLM 系統提示詞。"""
    context_blocks = "\n".join(
        f"[{i+1}] 來源：{c.doc_name} | {c.section} (p.{c.page})\n內容：{c.content}"
        for i, c in enumerate(retrieved)
    )
    return (
        "請僅依據下列檢索到的光達手冊與法規片段回答問題，每個關鍵數據後方都必須標註 [來源編號]；"
        "若資料中未提及，請直接說明查無記載。\n\n"
        f"### 參考片段\n{context_blocks}\n\n"
        f"### 使用者問題\n{query}"
    )

if __name__ == "__main__":
    user_q = "Zenmuse L2 飛行時 IMU 校準頻率與成果高程精度要求為何？"
    hits = hybrid_retrieve(user_q, model_filter="Zenmuse L2", top_k=2)
    print(build_rag_prompt(user_q, hits))
